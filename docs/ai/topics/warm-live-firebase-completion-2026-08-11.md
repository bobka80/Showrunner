## Doctrine (plain language)

**While warm:** browser ↔ Firebase for normal in-project edits (immediate, automatic).  
**Sheets:** publish only (checkpoint ~30m / End Room).  
**Humans:** no Start Prep / Start Collab / Save as everyday workflow. End Room stays explicit.

This is the industry-normal “live notebook + durable publish” pattern. Showrunner’s pain was **half migration** (PA/Timeline live after buttons; identity/Hub still Apps Script). This topic locks finishing that migration.

---

## Two meanings of “warm” (do not confuse)

| Meaning | What it is |
|---------|------------|
| Where truth lives | Firebase notebook while room open |
| How the browser reaches it | True live = browser ↔ Firebase; slow path = browser → Apps Script → Firebase |

**This campaign finishes meaning #2 for identity and ceremony**, and keeps #1 from Campaign Room.

---

## Formula / Triangle / auto-containers

Those brains already run in the **HTML equipment engine**. Live PA does not skip them — it runs them in the browser, then writes results to Firebase. Apps Script is not the per-edit formula referee in live mode.
